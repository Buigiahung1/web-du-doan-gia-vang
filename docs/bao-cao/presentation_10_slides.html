1. KIẾN TRÚC TỔNG THỂ: FRONT-END → BACK-END → DATABASE

Hệ thống phân tách 4 tầng độc lập (Separation of Concerns), giao tiếp qua RESTful JSON API chuẩn RFC

01 · FRONT-END LAYER Presentation & UI Client
  • • Vanilla JS ES6+, HTML5 Semantic, Tailwind CSS (Dark Mode).
  • • Chart.js vẽ nến Nhật OHLCV & dải sai số dự báo (90–95% tùy mô hình).

  • • FastAPI (Python 3.12/3.13) với máy chủ Uvicorn ASGI.
  • • OAuth2 Password Flow, JWT HS256 stateless, mã hóa Bcrypt.
  • • Pydantic V2 schemas kiểm tra chặt chẽ payload & query.
  • • Bộ đệm TTLCache giảm tải DB, Token Bucket Rate Limiter.

  • • Data Pipeline tính toán SMA, RSI, Volatility, Lags trễ.
  • • LightGBM Regressor tối ưu chuỗi thời gian.
  • • Mạng nơ-ron LSTM xử lý chuỗi trượt đa chiều.
  • • ModelRegistry nạp artifact nhị phân suy luận trực tiếp.
04 · DATABASE LAYER Cơ Sở Dữ Liệu Quan Hệ
  • • MySQL / SQLite thông qua lớp ánh xạ SQLAlchemy 2.0 ORM.
  • • Cấu trúc 3NF: 06 bảng thực thể lưu trữ người dùng, giá, dự đoán.
  • • 02 SQL Views (models, prediction_history) theo đề bài.
  • • Giao dịch ACID, ràng buộc khóa ngoại (FK) và Index.
LUỒNG DỮ LIỆU ĐỒNG BỘ: Client gửi Request (Fetch JSON) ➔ Backend FastAPI thẩm định & xác thực JWT ➔ Nạp dữ liệu DB + Chạy AI Inference ➔ Trả về JSON Response ➔ DOM cập nhật biểu đồ & bảng không reload.

100% các tính năng giao diện đều được ánh xạ và giao tiếp trực tiếp qua RESTful Endpoints

DỮ LIỆU GIÁ & THỊ TRƯỜNG

MỤC 5 · TRUYỀN DỮ LIỆU TỪ CLIENT 06 / 11

5. CÁCH GỬI DỮ LIỆU TỪ FRONT-END LÊN MÁY CHỦ (GET & POST)

Chuẩn hóa phương thức truyền tải qua URL Query Parameters, JSON Request Body và Form URL-Encoded

PHƯƠNG THỨC GET (QUERY PARAMS) Lọc dữ liệu lịch sử, lấy giá hiện tại, thống kê
  • • Nối trực tiếp key=value vào sau URL qua ký tự '?' và '&'.
  • • Mã hóa an toàn: Sử dụng encodeURIComponent() trong JavaScript.
  • • Cấu trúc Request thực tế:
    GET /api/gold/history?type=XAU_VND_LUONG&from=2026-01-01&to=2026-10-30&interval=day&page=1&page_size=20
  • • Hỗ trợ caching phía client và trình duyệt web.
PHƯƠNG THỨC POST (JSON PAYLOAD) Dự đoán giá vàng AI, Đăng ký người dùng mới
  • • Header bắt buộc: Content-Type: application/json.
  • • Đóng gói Payload qua JSON.stringify().
  • • Cấu trúc Request thực tế gửi lên POST /api/predict:
    {
  "gold_type": "XAU_VND_LUONG",
  "horizon_days": 7,
  "model_id": 2,
  "date_from": "2026-01-01",
  "date_to": "2026-10-30"
}
  • • Truyền tải cấu trúc phức tạp và an toàn dữ liệu.
FORM-DATA & XÁC THỰC JWT Đăng nhập OAuth2 Password & Giao dịch bảo mật
  • • Đăng nhập: application/x-www-form-urlencoded.
    Payload: URLSearchParams({ username, password }).
  • • Cơ chế tự động hóa trong Helper apiRequest():
    if (AppState.jwtToken) {
  headers['Authorization'] = 
    'Bearer ' + AppState.jwtToken;
}
  • • Token JWT lưu trong localStorage và giải phóng khi đăng xuất.
NGUYÊN TẮC AN TOÀN TRUYỀN DỮ LIỆU: Mọi request gửi lên đều được validate Regex phía Client trước khi gửi. Toàn bộ tham số nhạy cảm (mật khẩu) tuyệt đối không đưa vào URL Query Params mà bắt buộc truyền qua Body với kết nối bảo mật.
MỤC 6 · QUY TRÌNH XỬ LÝ BACK-END 07 / 11

6. CÁCH BACK-END TIẾP NHẬN, XỬ LÝ & TRẢ KẾT QUẢ VỀ CLIENT

Quy trình xử lý khép kín 4 bước từ tiếp nhận, kiểm soát bảo mật, chạy mô hình AI đến đóng gói JSON

BƯỚC 1: TIẾP NHẬN & VALIDATE Request Validation (Pydantic)
  • • FastAPI đón nhận Request qua Router tương ứng.
  • • Pydantic V2 kiểm tra kiểu số, ngày tháng hợp lệ.
  • • Kiểm tra logic: ngày bắt đầu <= ngày kết thúc; horizon_days ∈ [1, 7].
  • • Nếu sai: Trả về HTTP 422 Unprocessable Entity kèm mô tả lỗi.
BƯỚC 2: XÁC THỰC & BẢO MẬT Security & Middleware Layer
  • • Middleware giải mã JWT: Trích xuất user_id và role.
  • • RBAC: Endpoint Admin chặn ngay nếu role != 'admin' (HTTP 403).
  • • TTLCache: Nếu dữ liệu giá có trong cache, trả về tức thì.
  • • Token Bucket Rate Limiter giới hạn tần suất gọi API.
BƯỚC 3: XỬ LÝ DỮ LIỆU & AI Business Logic & Inference
  • • SQLAlchemy truy vấn N phiên giá lịch sử từ gold_prices.
  • • Tính toán SMA7, SMA21, RSI14, Volatility lùi 1 phiên (.shift(1)).
  • • Chạy AI Inference (LightGBM/LSTM), tính cận sai số dự báo (90–95% tùy mô hình).
  • • Ghi nhận bản ghi vào bảng predictions & prediction_items.
BƯỚC 4: ĐÓNG GÓI & PHẢN HỒI Response Serialization & GZip
  • • Pydantic Out Schema chuyển đổi Python Dict sang JSON chuẩn.
  • • Gắn Header thời gian thực thi: X-Process-Time-ms (< 15ms).
  • • Middleware GZip nén dữ liệu nếu dung lượng > 1000 bytes.
  • • Trả về HTTP 200 OK; Frontend gọi hàm renderDOM cập nhật UI.
MẪU KẾT QUẢ JSON TRẢ VỀ (POST /api/predict): {"prediction_id": 12, "trend": "Tăng", "last_actual": {"date": "2026-10-30", "price": 88500000}, "items": [{"target_date": "2026-11-02", "predicted_price": 89100000, "lower": 87800000, "upper": 90400000}, ...]}
MỤC 7 · THIẾT KẾ CƠ SỞ DỮ LIỆU 08 / 11

7. THIẾT KẾ CSDL: BẢNG, TRƯỜNG DỮ LIỆU, KHÓA CHÍNH/NGOẠI & QUAN HỆ

Lược đồ CSDL quan hệ chuẩn hóa 3NF gồm 06 bảng thực thể và 02 SQL Views tương thích

BẢNG USERS & GOLD_TYPES
■ users (Người dùng & Bảo mật)

• id (INTEGER, PK, Auto-increment)
• username (VARCHAR(50), Unique)
• email (VARCHAR(255), Unique)
• password_hash (VARCHAR(255), Bcrypt)
• role (VARCHAR(10), 'user'/'admin')
• is_active (BOOL), created_at (DATETIME)

■ gold_types (Danh mục loại vàng)

• id (INTEGER, PK, Auto-increment)
• code (VARCHAR(50), Unique - XAU_VND_LUONG)
• name (VARCHAR(100)), unit (VARCHAR(30))
• source (VARCHAR(100), Nguồn tham chiếu)

BẢNG GOLD_PRICES & ML_MODELS
■ gold_prices (Nến lịch sử OHLCV)

• id (INTEGER, PK, Auto-increment)
• gold_type_id (INTEGER, FK -> gold_types.id)
• date (DATE, Index), open, high, low, close
• volume, buy, sell (NUMERIC)
• Quan hệ: N - 1 với gold_types

■ ml_models (Quản lý mô hình AI)

• id (INTEGER, PK, Auto-increment)
• name (VARCHAR(50)), algorithm (VARCHAR(30))
• version (VARCHAR(20)), artifact_path (VARCHAR)
• metrics (JSON: MAE, MSE, RMSE, MAPE, R2)
• is_active (BOOL - trạng thái mặc định)

BẢNG PREDICTIONS & SQL VIEWS
■ predictions & prediction_items

• predictions: id [PK], user_id [FK], gold_type_id [FK], ml_model_id [FK], horizon_days, created_at.
• prediction_items: id [PK], prediction_id [FK], target_date, predicted_price, lower_bound, upper_bound.
• Quan hệ: 1 - N giữa lượt dự đoán và từng ngày.

■ 02 SQL Views Tương Thích Ngược

• VIEW models: Ánh xạ 1-1 từ ml_models.
• VIEW prediction_history: Ánh xạ từ predictions giúp khớp 100% tên 5 bảng theo đề cương.

MINH CHỨNG THỰC HÀNH · PHẦN 1 09 / 11

8. DEMO CÁC CHỨC NĂNG KẾT NỐI DATABASE: THÊM, XEM, SỬA, XÓA (CRUD)

Minh chứng thực tế thao tác dữ liệu hai chiều giữa Giao diện, Backend và Database

CHỨC NĂNG 1: QUẢN TRỊ BẢNG GIÁ ADMIN (FULL CRUD)

✔ XEM DỮ LIỆU (READ): Client gọi GET /api/gold/history?order=desc -> Backend thực thi truy vấn SQLAlchemy SELECT * FROM gold_prices -> Trả về danh sách nến và render bảng giá.

✔ THÊM MỚI (CREATE): Admin nhập form thêm giá ngày mới gửi POST /api/admin/prices -> Backend kiểm tra khóa trùng -> Thực thi INSERT INTO gold_prices -> Xóa TTLCache và cập nhật bảng giá.

✔ SỬA DỮ LIỆU (UPDATE): Bấm nút 'Sửa' trên hàng dữ liệu, nhập giá Close mới -> Client gửi PATCH /api/admin/prices/{id} -> Backend thực thi UPDATE gold_prices SET close = :newClose WHERE id = :id -> Cập nhật thành công.

✔ XÓA DỮ LIỆU (DELETE): Bấm nút 'Xóa', xác nhận dialog confirm -> Gửi DELETE /api/admin/prices/{id} -> Backend thực thi DELETE FROM gold_prices WHERE id = :id -> Bản ghi lập tức biến mất khỏi CSDL.

CHỨC NĂNG 2: DỰ ĐOÁN AI & LƯU LỊCH SỬ CÁ NHÂN

✔ GỬI THAM SỐ DỰ BÁO: Người dùng chọn loại vàng, số ngày (7 ngày), chọn Model và bấm 'Kích hoạt dự đoán' -> Gửi POST /api/predict kèm JWT Token.

✔ MỞ TRANSACTION GHI CSDL: Backend thực thi suy luận mô hình -> Mở transaction an toàn: INSERT INTO predictions (user_id, gold_type_id, ml_model_id, horizon_days, created_at) -> Sinh ra ID lượt dự đoán.

✔ LƯU CHI TIẾT TỪNG PHIÊN (1-N): Vòng lặp ghi nhận 7 dòng kết quả tương ứng 7 ngày dự báo vào bảng prediction_items (target_date, predicted_price, lower_bound, upper_bound) -> Commit transaction.
